A well-crafted design system is the backbone of any scalable product. Let's explore how Tailwind CSS and shadcn/ui make it practical to build one.

## Why shadcn/ui?

Unlike traditional component libraries, shadcn/ui gives you the source code. You own every component, which means:

- Full customization without fighting the library
- No version lock-in or breaking changes
- Copy-paste approach keeps your bundle lean

## Getting Started

Initialize shadcn/ui in your Next.js project:

```bash
npx shadcn@latest init
```

Then add components as you need them:

```bash
npx shadcn@latest add button card input
```

## Theming with CSS Variables

shadcn/ui uses CSS custom properties for theming, which pairs beautifully with Tailwind:

```css
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
}
```

## Component Composition

The real power comes from composing primitives into domain-specific components:

```tsx
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
import { Badge } from "@/components/ui/badge";

function PostCard({ title, tags }: { title: string; tags: string[] }) {
  return (
    <Card>
      <CardHeader>
        <CardTitle>{title}</CardTitle>
      </CardHeader>
      <CardContent>
        <div className="flex gap-2">
          {tags.map((tag) => (
            <Badge key={tag} variant="secondary">
              {tag}
            </Badge>
          ))}
        </div>
      </CardContent>
    </Card>
  );
}
```

## Consistency at Scale

The key to a successful design system is consistency. By centralizing your design tokens in CSS variables and building from a shared component library, every page in your application shares the same visual language.
